# 03. 피보나치 (Fibonacci)

같은 수열을 **재귀**와 **반복**으로 구현하고, 호출 횟수와 걸린 시간을 나란히
찍어 본다. 정의를 그대로 옮긴 코드가 왜 느려지는지 눈으로 보는 예제다.

```plaintext
F(0) = 0,  F(1) = 1,  F(n) = F(n-1) + F(n-2)
```

| 파일 | 내용 |
| --- | --- |
| `fibonacci.pseudo` | 두 방식의 절차 |
| `fibonacci.c` | C 구현 |
| `fibonacci.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다.

- 결과 (C)

```console
 n   재귀 호출 수        재귀(ms)   반복(ms)   F(n)
--- --------------- ---------- ---------- ----------
 10             177       0.00     0.0000         55
 20           21891       0.01     0.0000       6765
 30         2692537       0.82     0.0000     832040
 40       331160281     120.58     0.0000  102334155
```

`n`이 10 늘 때마다 재귀 호출 수가 **약 100배**가 됩니다. 반복은 `n`에 비례해
늘 뿐이라 표에서는 0으로 찍힙니다.

Python 쪽은 같은 코드가 훨씬 느려 `n = 35`까지만 돌립니다. 그것도 1초쯤
걸립니다. **어디서 멈추는지도 관찰의 일부입니다.**

## 왜 이렇게 벌어지나

`F(5)`를 재귀로 구하면 호출이 나무처럼 갈라집니다.

```plaintext
                  F(5)
           ┌───────┴───────┐
         F(4)             F(3)
      ┌───┴───┐        ┌───┴───┐
    F(3)     F(2)    F(2)     F(1)
   ┌─┴─┐    ┌─┴─┐   ┌─┴─┐
 F(2) F(1) F(1) F(0) F(1) F(0)
```

`F(2)`가 세 번, `F(1)`이 다섯 번 계산됩니다. **같은 값을 몇 번이고 다시
구합니다.** 반복은 앞의 두 항만 들고 나아가므로 각 항을 한 번씩만 구합니다.

| | 시간 | 공간 |
| --- | --- | --- |
| 재귀 | O(2^n) | O(n) (호출 스택) |
| 반복 | O(n) | O(1) |

## 바꿔 보기

- `n`을 45, 50으로 올려 보세요. 재귀가 언제 실용성을 잃는지 보입니다.
- 재귀가 느린 원인은 **중복 계산**이지 재귀 자체가 아닙니다. 이미 구한 값을
  저장해 두면 재귀도 O(n)이 됩니다. 그 방법은 주제 14(동적 계획법)에서
  다룹니다.
