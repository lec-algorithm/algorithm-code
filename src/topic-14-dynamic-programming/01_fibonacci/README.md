# 01. 피보나치 (Fibonacci)

주제 01의 피보나치 재귀를 다시 꺼낸다. 이번에는 **이미 구한 값을 적어
두는** 두 방식, 메모이제이션(하향식)과 타뷸레이션(상향식)을 함께 놓고
호출 수를 센다. 세 절차를 의사코드 하나에 C와 Python 두 구현으로 담았다.

| 파일 | 내용 |
| --- | --- |
| `fibonacci.pseudo` | 세 방식의 절차 |
| `fibonacci.c` | C 구현 |
| `fibonacci.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-14-dynamic-programming/01_fibonacci
make -f /work/Makefile fibonacci.out && ./fibonacci.out
python3 fibonacci.py
```

- 결과

```console
F(5)
  recursive  = 5, calls = 15
  memo       = 5, calls = 9
  memo       = [-1, -1, 1, 2, 3, 5]
  tabulation = 5
  dp         = [0, 1, 1, 2, 3, 5]

 n  recursive calls  memo calls                 F(n)
 10              177          19                   55
 20            21891          39                 6765
 30          2692537          59               832040
 90                -         179  2880067194370816120
```

두 구현이 같은 결과를 낸다. 재귀 호출 수(177, 21891, 2692537)는 주제 01의
표와 같은 숫자다. 메모를 붙이면 같은 재귀가 `2n - 1`번만 불린다.

`memo`의 0번과 1번 칸이 -1로 남은 것을 보자. `n <= 1`은 메모를 보기 전에
바로 돌려주므로 적을 일이 없다. `dp`는 0번부터 빠짐없이 채운다.

`n = 90`이면 재귀는 끝나지 않으므로 `-`로 건너뛴다. 메모는 179번 만에
답을 낸다. 그 값은 C의 `long long`에 들어가는 거의 마지막 항이다.

## 바꿔 보기

- `fibMemo`에서 메모를 확인하는 `if` 두 줄을 지워 보자. 호출 수가 재귀와
  똑같아진다. 빨라진 이유는 그 두 줄뿐이다.
- `fibTabulation`의 `dp` 배열을 변수 두 개로 줄여 보자. 그것이 주제 01의
  반복 구현이고, 공간이 O(1)이 된다.
