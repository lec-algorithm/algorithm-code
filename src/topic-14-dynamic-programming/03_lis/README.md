# 03. 최장 증가 부분수열 (LIS)

배열에서 순서를 지킨 채 몇 개를 골라 **순증가하는 가장 긴 수열**의 길이를
구한다. `[10, 9, 2, 5, 3, 7, 101, 18]`이면 4다 (예: `2 5 7 101`).
메모이제이션은 "고른다 / 안 고른다" 재귀에 `(i, prev)` 표를 붙이고,
타뷸레이션은 `dp[i]`(arr[i]로 끝나는 가장 긴 길이)를 채운 뒤 `prev`를
거꾸로 따라가 수열 하나를 복원한다.

| 파일 | 내용 |
| --- | --- |
| `lis.pseudo` | 두 방식의 절차와 점화식 |
| `lis.c` | C 구현 |
| `lis.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-14-dynamic-programming/03_lis
make -f /work/Makefile lis.out && ./lis.out
python3 lis.py
```

- 결과

```console
arr = [10, 9, 2, 5, 3, 7, 101, 18]

plain recursion = 4, calls = 108
memo hits (i, prev + 1)
  hit memo[7][7] = 0
  hit memo[7][7] = 0
  hit memo[6][6] = 1
  hit memo[7][7] = 0
  hit memo[6][6] = 1
  hit memo[7][7] = 0
  hit memo[6][6] = 1
  hit memo[5][5] = 2
  hit memo[4][4] = 2
  hit memo[7][7] = 0
  hit memo[7][7] = 0
memo = 4, calls = 62, hits = 11, filled 36 of 72

tab  = 4
  dp   = [1, 1, 1, 2, 2, 3, 4, 4]
  prev = [-1, -1, -1, 2, 2, 3, 5, 5]
  one LIS: 2 5 7 101
```

두 구현이 같은 결과를 낸다.

- 메모 없는 재귀는 108번 불렸고, 메모를 붙이면 62번이다. 표에서 바로 꺼낸
  것은 **11번**뿐이다. 72칸 중 36칸만 채웠다. 원소 8개짜리 배열에서는 같은
  `(i, prev)`가 생각보다 덜 겹친다. 배열이 길어질수록 차이가 벌어진다.
- `hit memo[7][7]`은 "7번 원소(18)를 볼 차례인데 마지막으로 고른 것이
  6번(101)"인 상황이다. 18은 101 뒤에 올 수 없으므로 답은 0이다.
- `dp`의 최댓값 4가 답이다. 101(6번)에서 `prev`를 따라가면 5번(7), 3번(5),
  2번(2)이고, 뒤집으면 `2 5 7 101`이다.

## 바꿔 보기

- 배열을 `[0, 1, 0, 3, 2, 3]`으로 바꿔 보자. 답은 4(`0 1 2 3`)다.
- 원소를 20개쯤으로 늘리고 `plain recursion`과 `memo`의 호출 수를 견주어
  보자. 메모가 왜 필요한지 숫자로 보인다.
- 최댓값을 찾을 때 `>`를 `>=`로 바꾸면 18로 끝나는 수열(`2 5 7 18`)이
  복원된다. 길이가 같은 답은 여럿일 수 있다.
