# 06. 0/1 배낭 (0/1 Knapsack)

용량이 정해진 배낭에 물건을 **통째로만** 담아 가치의 합을 최대로 하는 문제.
주제 06의 분할 배낭과 물건이 같다. 쪼갤 수 없게 바꾸자 그리디는 160에서
멈췄다. 여기서는 `dp[i][c]` 표를 채워 220을 찾고, 표를 거꾸로 따라가 담은
물건을 복원한다.

| 파일 | 내용 |
| --- | --- |
| `knapsack.pseudo` | 점화식과 절차 |
| `knapsack.c` | C 구현 |
| `knapsack.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-14-dynamic-programming/06_knapsack
make -f /work/Makefile knapsack.out && ./knapsack.out
python3 knapsack.py
```

- 결과

```console
capacity = 50
items: (w=10, v=60) (w=20, v=100) (w=30, v=120)

dp (columns every 10)
  i\c    0   10   20   30   40   50
  0      0    0    0    0    0    0
  1      0   60   60   60   60   60
  2      0   60  100  160  160  160
  3      0   60  100  160  180  220

best = 220
  take item 3 (w=30, v=120)
  take item 2 (w=20, v=100)
```

두 구현이 같은 결과를 낸다.

- 표는 용량 0부터 50까지 51칸을 다 채운다. 무게가 모두 10의 배수라
  10칸마다 하나씩만 찍었다. 사이 칸은 왼쪽 칸과 같다.
- 칸 하나는 **위 칸**(물건 i를 안 담음)과 **위 줄에서 w[i]만큼 왼쪽 칸 +
  v[i]**(담음) 중 큰 것이다. 맨 아래 오른쪽 220은 위의 160과 `dp[2][20] +
  120 = 220`을 견준 결과다.
- 복원은 아래에서 위로 간다. `dp[3][50] = 220`이 위 칸 160과 다르므로
  물건 3을 담았다. 용량 20으로 옮겨 `dp[2][20] = 100`이 위 칸 60과 다르므로
  물건 2를 담았다. `dp[1][0] = 0`은 위 칸과 같으니 물건 1은 담지 않았다.

## 바꿔 보기

- `capacity`를 40으로 바꿔 보자. 180(물건 1, 3)이 나온다.
- 물건 `(w=25, v=110)`을 하나 더 넣어 보자. `w`, `v`에 덧붙이고 `n`을 4로,
  `step`을 5로 바꾼다. 용량 50이면 무엇을 담는지 그리디의 순서와 견주어 보자.
