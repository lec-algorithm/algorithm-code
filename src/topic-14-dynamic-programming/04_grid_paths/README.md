# 04. 격자 경로 (Grid Paths)

격자의 `(0, 0)`에서 `(5, 5)`까지, 한 번에 `x+1` 또는 `y+1`로만 움직여 가는
**경로의 수**를 센다. `(2, 2)`, `(3, 3)`, `(4, 4)`는 장애물이라 지나갈 수 없다.
메모이제이션은 "여기서 끝까지", 타뷸레이션은 "처음부터 여기까지"를 센다.

| 파일 | 내용 |
| --- | --- |
| `gridPaths.pseudo` | 두 방식의 절차 |
| `gridPaths.c` | C 구현 |
| `grid_paths.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-14-dynamic-programming/04_grid_paths
make -f /work/Makefile gridPaths.out && ./gridPaths.out
python3 grid_paths.py
```

- 결과

```console
grid 6 x 6, (0, 0) -> (5, 5), obstacles (2, 2) (3, 3) (4, 4)

plain recursion = 48, calls = 439
memo            = 48, calls = 65, solved 32 cells
tab             = 48

  x\y    0    1    2    3    4    5
   0     1    1    1    1    1    1
   1     1    2    3    4    5    6
   2     1    3    #    4    9   15
   3     1    4    4    #    9   24
   4     1    5    9    9    #   24
   5     1    6   15   24   24   48
```

두 구현이 같은 결과를 낸다. 경로는 **48개**다.

- 표의 각 칸은 **위 칸 + 왼쪽 칸**이다. `(1, 1)`은 1 + 1 = 2, `(5, 5)`는
  24 + 24 = 48이다.
- 장애물 칸은 0으로 두고 `#`으로 찍었다. 장애물 바로 아래·오른쪽 칸은 한쪽
  길만 받는다. `(2, 3)`은 위의 4만 받고 왼쪽은 장애물이라 4다.
- 메모 없는 재귀는 439번, 메모는 65번 불렸다. 메모가 센 칸은 32개다.
  36칸에서 장애물 3칸과 목표 칸을 뺀 수다.

목표가 `(5, 5)`이면 격자가 더 커도 답은 같다. 오른쪽·아래로만 움직이므로
목표를 넘어간 칸은 쓰이지 않는다.

## 바꿔 보기

- `obstacles`를 비워 보자. 답은 252다. 10걸음 중 아래로 갈 5걸음을 고르는
  수 C(10, 5)와 같다.
- 목표를 `(10, 10)`으로 늘리고 메모 없는 재귀의 호출 수를 보자. 메모가
  왜 필요한지 숫자로 보인다.
