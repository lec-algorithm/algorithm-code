# 01. 해시 함수 (Hash Function)

키를 배열 인덱스 `[0, M-1]`로 바꾸는 함수를 몇 가지 돌려 본다. 정수 키는
M으로 나눈 나머지(모듈러 해싱)를 쓰고, 문자열 키는 글자를 숫자로 바꿔
섞은 뒤 나머지를 취한다. 마지막으로 키가 몇 개쯤 되면 충돌이 생기는지
확률을 셈한다. 같은 절차를 의사코드 하나에 C와 Python 두 구현으로 담았다.

| 파일 | 내용 |
| --- | --- |
| `hashFunction.pseudo` | 기준이 되는 절차. 두 구현은 이것을 옮긴 것이다 |
| `hashFunction.c` | C 구현 |
| `hash_function.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-08-hashing/01_hash_function
make -f /work/Makefile hashFunction.out && ./hashFunction.out
python3 hash_function.py
```

- 결과

```console
modular hashing, M = 8
  A (65) -> 1
  B (66) -> 2
  C (67) -> 3
  K (75) -> 3  collides with C

keys 0 4 8 12 16 20 24 28
  M = 8: 0 4 0 4 0 4 0 4  -> 2 of 8 buckets used
  M = 7: 0 4 1 5 2 6 3 0  -> 7 of 7 buckets used

string keys, M = 97
  key   sum  horner
  stop   66       9
  pots   66      79
  tops   66       3
  spot   66      49
  opts   66      58
  post   66      49

chance of at least one collision
  N =  3, M =  16:  18.0%
  N =  5, M =  16:  50.0%
  N = 10, M =  16:  97.4%
  N = 23, M = 365:  50.7%
```

두 구현이 같은 결과를 낸다. 네 덩어리를 차례로 보면 이렇다.

- `C`(67)와 `K`(75)는 8로 나눈 나머지가 둘 다 3이다. 서로 다른 키가 같은
  칸을 가리키는 **충돌**이다.
- 4의 배수인 키를 크기 8에 넣으면 0번과 4번 칸만 쓰인다. 키와 M이
  공약수 4를 가지기 때문이다. 소수 7로 바꾸면 일곱 칸이 다 쓰인다.
- 같은 글자로 된 여섯 단어는 글자 코드를 더하기만 하면 모두 66이 된다.
  자리마다 31을 곱하는 호너 방식은 다섯 칸으로 흩는다. `spot`과 `post`는
  그래도 49에서 만난다.
- 16칸에 키 5개만 넣어도 충돌이 한 번 이상 일어날 확률이 절반이다. 23명이
  모이면 생일이 같은 두 사람이 있을 확률이 절반을 넘는 것과 같은 계산이다.

## 바꿔 보기

`hornerHash`의 `R`을 1로 바꿔 보자. 곱하는 수가 1이면 더하기와 같아져서
여섯 단어가 다시 한 칸에 모인다. `M = 7` 줄의 키를 7의 배수로 바꾸면 이번에는
소수 7도 한 칸만 쓴다. 소수는 흔한 패턴에 강할 뿐, 모든 키에 강한 것은 아니다.
