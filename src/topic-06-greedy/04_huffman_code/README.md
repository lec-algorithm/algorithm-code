# 04. 허프만 코드 (Huffman Code)

문자마다 나온 횟수를 세고, **가장 드문 두 트리부터** 합쳐 코드 트리를
만든다. 흔한 문자는 짧은 코드, 드문 문자는 긴 코드를 받는다. 만든
코드로 인코딩하고, 트리를 따라 디코딩해 원문이 돌아오는지 확인한다.
같은 절차를 의사코드 하나에 C와 Python 두 구현으로 담았다.

| 파일 | 내용 |
| --- | --- |
| `huffmanCode.pseudo` | 기준이 되는 절차. 두 구현은 이것을 옮긴 것이다 |
| `huffmanCode.c` | C 구현 |
| `huffman_code.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-06-greedy/04_huffman_code
make -f /work/Makefile huffmanCode.out && ./huffmanCode.out
python3 huffman_code.py
```

- 결과

```console
text = ABRACADABRA!
freq : !=1 A=5 B=2 C=1 D=1 R=2

merge 1: !(1) + C(1) -> !C(2)
merge 2: D(1) + !C(2) -> D!C(3)
merge 3: B(2) + R(2) -> BR(4)
merge 4: D!C(3) + BR(4) -> D!CBR(7)
merge 5: A(5) + D!CBR(7) -> AD!CBR(12)

codes: !=1010 A=0 B=110 C=1011 D=100 R=111
encoded = 0110111010110100011011101010
bits: huffman 28, fixed 3-bit 36, ascii 96
decoded = ABRACADABRA!
```

두 구현이 같은 결과를 낸다. 다섯 번 합치면 트리 하나가 남는다.
다섯 번 나온 `A`는 1비트, 한 번씩 나온 `!`와 `C`는 4비트를 받았다.
12글자가 ASCII로 96비트, 문자 6종을 3비트 고정 길이로 적으면 36비트,
허프만은 **28비트**다. 디코딩하면 원문이 그대로 돌아온다.

## 같은 가중치는 어떻게 고르나

`!`·`C`·`D`처럼 가중치가 같은 트리가 여럿이면 어느 것을 먼저 꺼내느냐에
따라 트리 모양이 달라진다. 이 구현은 **트리 안의 가장 작은 문자**(ASCII
순)가 앞서는 것을 먼저 꺼내고, 먼저 꺼낸 쪽을 왼쪽(0)에 둔다. 규칙이
달라도 총 비트 수(28)는 같다. 허프만 코드는 하나가 아니지만 그 길이는
언제나 최적이다.

## 바꿔 보기

`text`를 바꿔 보자. `AAAAAAAAAB`처럼 한 문자가 압도적이면 압축이 잘 되고,
모든 문자가 고르게 나오면 고정 길이와 별 차이가 없다. 허프만이 이득을
보는 곳은 **빈도가 고르지 않은** 데이터다.
