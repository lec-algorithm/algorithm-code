# 07. 스택과 큐 (Stack, Queue)

스택은 나중에 넣은 것이 먼저 나오고(LIFO), 큐는 먼저 넣은 것이 먼저
나온다(FIFO). 두 자료구조를 배열로 만들고, LSD 기수 정렬의 **버킷**으로
써 본다. 자리마다 원소를 버킷 10개에 흩었다가 0번부터 차례로 모으는
방식이다. 같은 절차를 의사코드 하나에 C와 Python 두 구현으로 담았다.

| 파일 | 내용 |
| --- | --- |
| `stackQueue.pseudo` | 기준이 되는 절차. 두 구현은 이것을 옮긴 것이다 |
| `stackQueue.c` | C 구현 |
| `stack_queue.py` | Python 구현 |

## 실행

파일을 열고 편집기 오른쪽 위 **▶ 버튼**을 누릅니다. C와 Python 모두 됩니다.

터미널에서 직접 돌리려면 이렇게 합니다.

- 실행

```sh
cd src/topic-09-radix-sort/07_stack_queue
make -f /work/Makefile stackQueue.out && ./stackQueue.out
python3 stack_queue.py
```

- 결과

```console
push   : A B C D
pop    : D C B A
enqueue: A B C D
dequeue: A B C D

input        : 437 042 531 008 074
queue exp 1  : 531 042 074 437 008
queue exp 10 : 008 531 437 042 074
queue exp 100: 008 042 074 437 531
stack exp 1  : 531 042 074 437 008
stack exp 10 : 008 437 531 042 074
stack exp 100: 074 042 008 437 531
queue sorted = yes, stack sorted = no
```

두 구현이 같은 결과를 낸다. 위 네 줄이 LIFO와 FIFO다. A, B, C, D를
넣으면 스택은 D부터, 큐는 A부터 나온다.

아래는 같은 입력을 큐 버킷과 스택 버킷으로 정렬한 것이다. 큐 버킷은
`01_lsd_radix_sort`의 카운팅 정렬과 패스마다 똑같은 결과를 낸다.
스택 버킷은 첫 패스까지는 같다. 일의 자리가 모두 달라 한 버킷에 둘이
들어간 적이 없기 때문이다. 십의 자리에서 `531`과 `437`이 버킷 3에 함께
들어가는데, 스택은 나중에 넣은 `437`을 먼저 꺼낸다. 앞 패스가 만든
순서(일의 자리 1 < 7)가 뒤집혔다. 백의 자리에서도 버킷 0의 `008`, `042`,
`074`가 거꾸로 나와 최종 결과가 틀렸다.

## 바꿔 보기

입력을 `{21, 12, 11, 22}`로 바꿔 보자. 두 패스 모두 버킷마다 원소가 둘씩
들어가 스택 쪽 결과가 `{12, 11, 22, 21}`처럼 크게 어긋난다. 카운팅 정렬의
3단계를 앞에서부터 배치하도록 바꾼 것은 스택 버킷과 똑같이 틀린다.
